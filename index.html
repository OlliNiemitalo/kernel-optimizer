Circular blur kernel optimizer

An out-of-focus lens spreads each point of light into a disc, which is slow to compute directly. Following Olli Niemitalo's article Circularly symmetric convolution and lens blur, the disc is approximated by a sum of a few phased Gaussians, which can be computed as fast horizontal and vertical 1-D blur passes. The blur demo renders with the current kernel, including depth of field for videos with depth. The kernel optimizer searches for kernels closer to the disc.

Kernel optimizer

The kernel K(x, y) is circularly symmetric: K(x, y) = k(√(x² + y²)), where k(x) is its profile along a radius, x being the distance from the center in disc radii. The target profile is 1 inside the disc (x ≤ 1) and 0 beyond a transition band at its edge (x ≥ 1 + transition bandwidth), with no target in between. The ripple is the largest deviation of k from the target; the optimizers minimize it. Presets are the kernels published in the article. The GPU search uses jax-js-nonconsuming.

About the parameters

The profile k(x) is a sum of components, each (r cos(c x²) + i sin(c x²))·e−b x², with decay b, frequency c and weights r and i.

Multiplicity, per component, 1 to 10: m coinciding rates in closed form, (a0 + a1 r² + … + am−1 r2(m−1))·eλr², costing 2m rendering terms (1 = single, 2 = merged pair). Example: 2, 2, 1. More in the README.

About the negative-value penalty

Errors where the kernel is negative are multiplied by this penalty. Above 1, the optimizers trade ripple for fewer negative values, which look like cheap sharpening (as in the article's non-negative sets).

Differential evolution

Global search. With exact weights, it searches the decays b and frequencies c, and each candidate's weights are solved; otherwise it searches all parameters.

Remez exchange refinement

Refines all parameters of the current kernel, minimizing the ripple exactly.

How it works

Minimax on the dense grid (Dense grid samples per band, below), in double precision on the CPU. First solves the optimal weights for the current decays and frequencies exactly by an exchange (dual simplex) algorithm. Then each iteration tries a trust-region Gauss–Newton step whose linearized minimax problem is solved by exchange, and Newton steps on the equal-ripple (Remez) equations of the extremal points, keeping whichever lowers the ripple. Stops when no step improves. Usually converges in a few iterations from a kernel near a local optimum.

Gradient fine-tuning

Refines all parameters of the current kernel, minimizing a smooth approximation of the ripple.

How it works

Minimizes a log-sum-exp smooth maximum of |error| on the dense grid with Adam in parameter-relative units (learning rate defaults to 0.001/3N−2 and halves every third of the run; sharpness, relative to the current ripple, rises 10×). Keeps the best kernel by true maximum error.
